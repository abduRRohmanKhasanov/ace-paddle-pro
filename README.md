# Table Tennis Club SaaS — UX/UI спецификация (v1)

> Как пользоваться этим файлом: это не код и не готовый дизайн, а описание решений — какие поля, состояния и переходы должны быть на каждом экране. Скорми его агенту в Cursor целиком в начале работы над фичей, или кидай конкретный раздел, когда просишь сделать конкретный экран. Цвета/иконки описаны как *намерение*, а не как точные hex-коды дизайн-системы — их агент должен предложить сам под ваш стек.

---

## 1. Продукт в двух словах

Мультитенантный SaaS для клубов настольного тенниса. Каждый клуб — свой поддомен (`club-name.saas-service.com`), устанавливаемое PWA с названием и ярлыком клуба на экране телефона. **Mobile-first**: все экраны спроектированы в первую очередь под смартфон.

**Три роли в v1:**

1. **Администратор клуба** — создаёт клуб, управляет игроками и турнирами

2. **Игрок** — без аккаунта в v1, карточку заводит администратор, только просмотр

3. **Судья** — временная роль, без аккаунта, доступ к одному конкретному столу через ссылку/QR

**Сознательно отложено на v2:** аккаунты игроков и привязка карточки к аккаунту, оплата/тарифы SaaS, служба поддержки платформы (интерфейс уже есть, бэкенда пока нет).

---

## 2. User flow по ролям

### Администратор — настройка клуба (разовая, при создании)

1. Регистрация и создание клуба — название, поддомен (с live-проверкой занятости), ярлык для PWA

2. Настройка внешнего вида — цвет клуба

3. Рейтинговое ядро — выбор формулы расчёта рейтинга

4. Регламент и поддержка — правила клуба, контакты

### Администратор — регулярная работа

1. Добавление игроков — карточки без аккаунтов

2. Создание турнира — формат, даты, правила

3. Настройки турнира — тип сетки, влияние на общий рейтинг

4. Назначение судей на столы — ссылка или QR-код

5. Публикация результатов — обновление рейтингов и ленты новостей (автоматически)

### Игрок

1. Открытие приложения клуба — по ссылке/QR от админа или установленное PWA

2. Лента клуба — новости, автогенерируемые по итогам турниров

3. Профили игроков — рейтинг, бейджи, достижения, прогресс

4. Сравнение игроков и регламент

### Судья

1. Получение ссылки на стол — от администратора (QR или ссылка в мессенджере)

2. Открытие интерфейса стола — без регистрации, доступ только к этому столу

3. Ведение живого счёта — очко за очком, видит смену подачи и сторон

4. Отправка результата — обновление сетки турнира и рейтингов

## 3. Сквозные решения дизайн-системы

- **Цвет клуба** — администратор выбирает из *ограниченного, курированного набора* цветов (не произвольный hex), каждый заранее проверен на читаемость в светлой и тёмной теме. Хранить нужно один hue, а конкретный тон для текста/иконок пересчитывать отдельно под каждую тему — иначе в тёмном режиме цвет либо тусклый, либо нечитаемый.

- **Уровни игроков** — всегда обозначаются латиницей: `L1`, `L2`, `L3`… (L1 — сильнейшие). Рассчитываются от рейтинга.

- **Медали топ-3 в рейтинге** — 1 место золото, 2 серебро, 3 бронза (цвет — на бейдже с порядковым номером, не на аватарке).

- **Тренд** — зелёная стрелка вверх / красная стрелка вниз / серый тире для «без изменений». На экране полного рейтинга — это изменение **позиции в таблице** за последний турнир (сколько мест вверх/вниз), не изменение очков.

- **Значок чемпиона** — золотая корона рядом с именем = действующий чемпион клуба; серая/приглушённая корона = экс-чемпион (был чемпионом хотя бы раз).

- **Постоянные компоненты на всех «клубных» экранах игрока:**

  - Шапка: название клуба (крупно, цветом клуба) + колокольчик уведомлений + шестерёнка настроек

  - Нижняя навигация игрока: Лента / Рейтинг / Профиль / Регламент

- **Постоянные компоненты на всех экранах администратора:**

  - Та же шапка

  - Нижняя навигация админа: Дашборд / Игроки / Турниры / Настройки

- **Модальные экраны** (создание игрока, турнира, назначение судьи и т.п.) — заголовок по центру/слева + крестик закрытия справа. Без текстовой кнопки «Отмена» слева.

## 4. Экраны администратора

### 4.1 Онбординг — мастер из 4 шагов

**Шаг 1. Создание клуба**

- Название клуба (текст)

- Поддомен — live-проверка занятости в реальном времени, превью полного адреса (`name.saas-service.com`)

- Ярлык для приложения — загрузка иконки, появится на экране телефона при установке PWA

**Шаг 2. Внешний вид**

- Выбор цвета клуба из курированной палитры (см. раздел 3)

- Предпросмотр сразу в двух темах (светлая/тёмная) рядом, чтобы админ видел, что цвет не потеряется в дарк-моде

**Шаг 3. Рейтинговое ядро** — три варианта на выбор, каждый с кратким описанием плюсов/минусов:

- **Эло (Elo)** — классическая формула, простая. Не учитывает уверенность рейтинга новичков

- **Glicko-2** (рекомендуется по умолчанию) — как Эло, но быстрее находит уровень новых и давно неактивных игроков

- **Простые очки** — победа = +N очков, поражение = 0. Легко объяснить, менее точно учитывает силу соперника

- Предупреждение: смена ядра позже возможна, но история рейтинга начнётся заново

**Шаг 4. Регламент и поддержка**

- Текстовое поле — регламент клуба (правила, которые увидят игроки)

- Контакт поддержки клуба (Telegram)

- ⚠️ **Несостыковка, которую стоит поправить при разработке:** здесь собирается общий «контакт поддержки», а на итоговом экране регламента (см. 5.5) контакты разделены на три типа — админ клуба, поддержка платформы, разработчик. Имеет смысл, чтобы этот шаг явно собирал именно телеграм самого администратора, а не общий «support».

### 4.2 Дашборд администратора (после создания клуба)

- Карточка активного турнира (если идёт) — название, прогресс «сыграно X из Y матчей», прогресс-бар, кнопка «Управлять турниром»

- Два тайла быстрого доступа: «Игроки» (счётчик) и «Турниры» (счётчик завершённых)

- Мини-лента последней активности (2–3 строки, например «Судья назначен на стол 2»)

- Добавление игрока сюда **не** выносится (см. 4.3) — на дашборде это было бы нелогично рядом с идущим турниром

### 4.3 Список игроков

- Заголовок со счётчиком «Игроки · 42»

- Поиск по имени

- Список карточек: аватар/инициалы, имя, рейтинг + уровень (`L1`/`L2`/`L3`), три точки → меню редактировать/удалить

- Кнопка добавления игрока — плавающая кнопка «+» в правом нижнем углу **именно на этом экране**, не на дашборде

### 4.4 Добавление игрока (модалка)

- Фото (необязательно, если нет — используются инициалы)

- Имя и фамилия (обязательно)

- Начальный рейтинг (предзаполнен значением клуба по умолчанию, можно поменять)

- Телефон (необязательно) — «понадобится, если игрок позже привяжет аккаунт» (задел под v2)

### 4.5 Создание турнира (модалка)

- Название турнира

- Даты проведения (начало/конец)

- Формат — 4 варианта карточками с описанием:

  - **Круговая** — каждый играет с каждым, точнее, но дольше

  - **Олимпийка** (тег «Быстрый турнир») — выбывание после одного поражения

  - **Группы + два финала** — второй финал изолированный (не влияет на первый)

  - **Пары + два финала** — победитель второго финала получает «дикую карту» и играет в первом финале

- Переключатель «Учитывать в рейтинге клуба» (не все турниры должны влиять на рейтинг)

- Фильтр «Кто может участвовать» — Все уровни / L1 / L2 / L3

### 4.6 Назначение судей на столы

- Список столов турнира, у каждого:

  - Статус матча (идёт / ожидает) + кто играет

  - Статус судьи — **не имя человека**, а просто индикатор: зелёная точка «Судья назначен» / красная точка «Судья не назначен» (судья не обязательно имеет аккаунт, поэтому его личность не привязана к UI)

  - Для неназначенных: кнопка «Судить самому» (админ берёт стол на себя) **или** QR-код/ссылка, которую можно скопировать или отправить в мессенджер

### 4.7 Настройки клуба (после онбординга, через шестерёнку в шапке)

Список разделов, каждый ведёт на соответствующий редактор (тот же UI, что и в онбординге, но теперь редактируемый в любой момент):

- Информация о клубе (название, поддомен)

- Внешний вид (цвет)

- Рейтинговое ядро (показывает текущий выбор)

- Регламент клуба

## 5. Экраны игрока

### 5.1 Лента клуба (главный экран)

- Шапка (см. раздел 3)

- **Карточка чемпиона** первым элементом ленты — цветной акцентный фон, надпись «Действующий чемпион клуба» сверху, аватар + имя, дата последнего турнира

- Далее — автогенерируемые новости, каждая с иконкой по типу события:

  - Завершение турнира (кто победил, сколько участников)

  - Рост игрока в рейтинге

  - Новый бейдж/достижение

  - Рекорд (например, серия побед)

  - Анонс предстоящего турнира

  - У каждой карточки: иконка, заголовок, короткое описание, относительное время («2 ч назад»)

### 5.2 Профиль игрока

**Карточка сверху (шапка профиля), всё в одном блоке:**

- Аватар слева (не по центру), справа от него — имя + иконка короны (если чемпион/экс-чемпион), под именем дата вступления в клуб и место в рейтинге клуба

- Крупно — текущий рейтинг + динамика (зелёная стрелка вверх/вниз с числом)

- Строка из 4 показателей: Матчи / Победы / % побед / Уровень (бейдж `L1`)

**Три вкладки под карточкой:**

- **Награды** — сетка именных достижений (лучший на приёме, лучший на подаче, лучшие серии побед, лучшие камбэки, самые длинные серии очков, стальные нервы и т.п.), иконка + название на каждой

- **Матчи** — список матчей от последнего к первому, у каждого: соперник, дата, счёт по сетам, кнопка-индикатор результата (Победа — зелёным / Поражение — красным)

- **Рейтинг** — текущий рейтинг + изменения за неделю/месяц/год/всё время, график динамики, ниже история изменений: **новые записи сверху**, турнирные записи сворачиваемые (при разворачивании — **последний матч турнира тоже первым**), можно показывать и запись за отдельный матч вне турнира

Кнопка «Сравнить с другим игроком» — видна под каждой из трёх вкладок, не только под одной.

### 5.3 Полный рейтинг клуба

- Фильтр по уровню (Все уровни / L1 / L2 / L3)

- Список игроков с местом в рейтинге:

  - Топ-3 — медальный бейдж на месте порядкового номера (золото/серебро/бронза)

  - Аватар, имя (+ корона чемпиона/экс-чемпиона при наличии), уровень

  - Рейтинг + тренд позиции за последний турнир (▲/▼/— с числом позиций)

  - Своя строка в списке подсвечена и помечена «Вы»

### 5.4 Сравнение двух игроков

- Верх: два игрока side-by-side с «VS» между ними (аватар + имя)

- Построчное сравнение: Рейтинг, Уровень, Матчи, % побед — сторона, где показатель выше, выделена зелёным и жирным; при равенстве — нейтральный серый

- Блок личных встреч — счёт очных матчей между этими двумя игроками

- Кнопка «Сравнить с другим» — сменить второго игрока

### 5.5 Регламент

Разделён на **два уровня правил:**

- **Правила платформы** — общие для всех клубов на SaaS, не редактируются администратором конкретного клуба (например: кто фиксирует официальный результат, как считается рейтинг, требование уважительного поведения)

- **Регламент клуба «[название]»** — то, что написал администратор именно этого клуба (обувь, время бронирования стола, опоздания и т.п.)

**Три канала связи:**

- Администратор клуба — Telegram, активен

- Служба поддержки платформы — временно недоступна (визуально приглушена), появится «в следующих версиях», когда сервис станет полноценным мультитенантным SaaS

- Разработчик — Telegram, активен

## 6. Экран судьи

### 6.1 Живой счёт на столе

Минимальная шапка — **без** обычного клубного header/nav (судья не залогинен в клуб): название турнира + номер стола, подпись «Судейский режим · без входа в аккаунт».

- Индикатор текущего сета: «Сет 2 · Сеты 1:0»

- Два больших тап-блока со счётом — вся площадь блока с именем и цифрой является зоной для добавления очка

- Индикатор подачи — один визуальный сигнал (подсветка блока подающего + точка рядом с именем), это **единое** обозначение «кто сейчас подаёт», отдельного индикатора «кто лидирует» не нужно — это и так видно по самим цифрам счёта

- Строка-подсказка: когда будет смена подачи («смена через 1 очко») и правило смены сторон в решающем сете

- Кнопки внизу: «Отменить очко» (undo — критично для реального использования, ошибки при вводе неизбежны) и «Завершить сет»

## 7. Открытые вопросы для разработки

- Как именно игрок физически узнаёт о клубе и получает доступ — админ распространяет ссылку/QR через соцсети или печатает на стенде в клубе. Нужен отдельный маленький флоу для генерации этой ссылки/QR (аналогично QR на судью).

- Судья: ссылка на стол может быть постоянной (закреплена за столом на всё время турнира) или разовой персональной (отправляется конкретному человеку) — нужно решить на уровне бэкенда, в UI заложены оба варианта.

- Что видит игрок, если переходит по ссылке клуба без указания конкретного игрока/турнира — то есть общий пустой/дефолтный сценарий входа.

- Как выглядит клуб без единого проведённого турнира (пустые состояния ленты, рейтинга, профиля).

## 8. Сознательно отложено на v2

- Оплата и тарифы SaaS

- Реальный бэкенд службы поддержки платформы (сейчас просто задизайнено состояние «недоступно")
